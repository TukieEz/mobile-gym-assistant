# Context Updater Protocol

> Выполняется ПОСЛЕ завершения работы (spark, coder)

## Когда обновлять контексты

Обновляй `.claude/contexts/*.md` если:
- Добавлен новый паттерн который стоит запомнить
- Изменилась архитектура домена
- Найден важный edge case
- Обнаружен anti-pattern который нужно задокументировать

## Алгоритм

### 1. Проанализируй сделанные изменения

```
Вопросы:
- Что нового узнали о домене?
- Какие паттерны использовали?
- Какие ошибки встретили?
- Что должен знать следующий агент?
```

### 2. Определи нужно ли обновление

**ДА, обновляй если:**
- Новый API/endpoint/tool
- Изменение в data model
- Новый workflow
- Важное ограничение

**НЕТ, не обновляй если:**
- Просто bug fix
- Рефакторинг без изменения логики
- Мелкие правки

### 3. Обнови контекст минимально

```markdown
## Добавь в нужную секцию:

### Новый паттерн
- Описание
- Пример кода
- Когда использовать

### Новое ограничение
- Что нельзя делать
- Почему
- Альтернатива
```

### 4. Проверь размер

```
Контекст файл должен быть < 500 строк.
Если больше — вынеси в отдельный файл и сделай ссылку.
```

## Пример

**После добавления нового seller tool:**

```markdown
# Обновление .claude/contexts/seller.md

## Tools (добавить в секцию)

### get_product_reviews (NEW)
- Получает отзывы о товаре с WB
- Параметры: `product_id: int`, `limit: int = 10`
- Возвращает: `list[Review]`
- Ограничение: max 100 отзывов за запрос
```

## Важно

- Пиши кратко — это контекст, не документация
- Фокус на том что нужно ЗНАТЬ, не на истории изменений
- Если сомневаешься — лучше не обновлять
